# 蜘蛛接龍 · 50 局已驗證可解的一花色牌桌

入口：`../spider.html`。原生 HTML/CSS/JS，零相依套件、零後端，沒有外部字型或追蹤。需一併發布此目錄的檔案。

## 規則與操作

- 104 張黑桃，每點數 8 張；10 列，前 4 列各 6 張，後 6 列各 5 張，只有每列最上層牌翻開，合計 44 張暗牌
- 剩餘 50 張備牌，5 次各 10 張；所有列都非空才可發下一排
- 牌接到大 1 點的牌上；同花色連續降冪牌串可一起移動；空列可放任意合法單牌／牌串
- 完整 K→A 自動收起，收完 8 組獲勝；移開覆蓋牌後自動翻開下一張
- 點選後點目標列，或桌面拖曳；手機維持可讀牌張尺寸，用牌桌內水平捲動查看 10 列
- `復原` 無人為次數上限，包括發牌、翻牌及自動收牌；存檔重載會重播操作紀錄並重建所有復原快照
- `牌局` 選單可選 01–50，切換保留每局進度；`新牌局` 優先打開尚未開始的牌局；`重新開始` 在有進度時要求確認
- `提示` 在已知路線提供可解證明下一步；偏離後明確改為僅合法的建議，不宣稱保證通關
- `解法演示` 沿完全匹配的證明狀態執行；偏離後須先確認重開，絕不硬套過期動作；可隨時暫停、接手及復原
- Ctrl / Cmd + Z 復原，Esc 取消選牌；瀏覽器 localStorage 自動保存各局操作與時間，無法保存時顯示警告

標準數位版規則來源：[MobilityWare Spider 規則](https://mobilityware.helpshift.com/hc/en/11-spider/faq/586-how-do-i-play-spider-solitaire/)。此版本選用一花色、限制發牌（禁止空列發牌）及無限復原。沒有修改規則以保證獲勝。

## 構造方式與保證範圍

`generate.py` 使用固定種子 701001–701050，在正常 54/50 發牌架構中構造一條合法收牌路線，並固定沿途各牌的點數。建構時每張牌只指定一次點數，最終恰好每點數 8 張。備牌發放穿插在移動過程，從未讓空列發牌。所有暗牌都必須在實際解法中翻開。

這些是**構造式、較容易的可解牌局，不是均勻隨機洗牌，也不是任意中途局面都保證可解**。各局有 96–99 個證明動作，需整理完 8 組、翻開 44 張暗牌並發出全部 5 排。50 份解法合計 4,911 個合法動作，其中 46 次為多張牌串移動。

固定牌張 ID 只是實體標識，點數配置因牌局而異。獨立驗證器把牌張 ID 移除，將每列的初始牌點序列與它對應的 5 張備牌作為一條軌跡，再排序這 10 條軌跡，因此即使任意整列連同備牌換位，也只會算成同一局。以這個較嚴格的比較，50 局仍全數不同；並非換編號、換花色或調換欄位冒充新牌局。

## 重現與驗證

在本資料夾執行，僅需 Python 3 與 Node.js 18+：

```sh
python3 generate.py
python3 verify.py
node test.js
node ui-test.js
node --check ui.js
```

從儲存庫根目錄也可執行：

```sh
python3 games/spider/verify.py
node games/spider/test.js
node games/spider/ui-test.js
```

- `deals.json`：50 份完整配置及完整逐步 witness（解法證明）
- `deals.js`：完全相同的瀏覽器資料，Node 測試會確認與 JSON 一致
- `engine.js`：實際遊戲的純函式規則引擎；每次動作都嚴格檢查合法性，沒有給證明路線特權
- `verify.py`：另一份獨立規則實作，**不匯入**遊戲引擎或生成器；檢查 104 張唯一實體牌、每點數 8 張、54/50 初始結構、44 張暗牌、逐步移動與發牌、翻牌、移除、牌張守恆、8 組完成、五輪發牌及布局唯一性
- `verification.json`：逐局驗證結果，包括牌局編號、動作數、每次發牌步驟、暗牌翻開數、收牌組數與欄位不變點數布局 SHA256
- `test.js`：實際 JS 引擎全數證明重播、逐步卡牌守恆、每一步逆向還原、保存／重載及非法動作回歸
- `ui-test.js`：無套件 DOM 事件模擬測試；涵蓋 50 局選單、點牌移動、提示、存檔重載+撤銷、偏離解法確認／取消、完整演示、收牌後撤銷、暫停取消計時器、規則／證明對話框、備牌撤銷及重開

目前測試結果：50 局 / 4,911 個合法動作 / 400 組完整 K→A / 2,200 張暗牌揭露 / 250 次合法十張發牌 / 50 個欄位不變唯一布局，全部通過。

## 真實瀏覽器視覺 QA

DOM 模擬測試**不等同瀏覽器渲染測試**。發布者另需在實際站點開啟 `games/spider.html`，建議桌面 1366×768、手機 390×844：

1. 開局 10 列共 54 張、僅 10 張正面，5 排備牌；桌面主介面不超出單一視窗，手機僅牌桌水平捲動，牌面點數可讀
2. 按 `提示`，按提示選牌及目標列；試非法移動；測拖曳、Esc、Ctrl/Cmd+Z
3. `發下一排` 後 `復原`，確認備牌、牌面、翻牌完整恢復；有空列時按發牌應被拒絕
4. `解法演示` → 暫停 → 復原 → 繼續；完整播放至勝利再復原最後一步；檢查 8 組收牌與 0 張備牌
5. 改走一個合法但不同的動作，再按演示；先取消確認，確保沒有改變局面，再確認重開
6. 切至第 50 局、移動並重新整理，確認保存；切回第 1 局確認各局進度獨立
7. 開關 `規則`、`可解認證`；確認返回首頁以及報告連結；在窄螢幕左右滑動看到全部十列

`window.spiderQA.snapshot()` 是只讀診斷快照，可讓瀏覽器 QA 檢查局號、動作、完成牌組、備牌及演示是否停止。一般玩法不依賴此診斷介面。
