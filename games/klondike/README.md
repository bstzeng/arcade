# 經典接龍 · 翻一張

入口：`../klondike.html`。無套件、無後端、無建置；也可直接以檔案開啟。UI、規則和所有證明資料隨站台一起交付。

## 明訂的版本

- 標準 52 張牌，每張唯一；黑桃、紅心、梅花、方塊各 13 張
- 七個牌列由 1 張到 7 張，僅各列頂牌朝上；剩餘 24 張放牌庫
- 牌列紅黑交錯、由大到小；可拆移任何合法的正面連續牌組；空位限 K 或 K 起頭的牌組
- 移走最後一張正面牌時，自動翻開下一張覆牌
- 每次翻一張；僅翻牌區頂牌可移動；牌庫清空後可無限回收，原順序不洗牌
- 四個完成區各花色由 A 排到 K；頂牌可移回牌列；移動、翻牌、回收各計一步
- 完成區共收齊 52 張即勝利

牌組、發牌、交錯遞減和空位 K 等基本規則核對 [Bicycle 的 Klondike 規則](https://bicyclecards.com/how-to-play/klondike)。Bicycle 該頁描述翻三張版本；本站明確採用上列「翻一張、無限回收、可拆移合法牌組、完成區可退牌」版本，未把來源的變體差異隱藏起來。

## 50 局的有解證明

`deals.js` 精確包含 **50** 個固定牌局。`generate.cjs` 從種子 93001 起，用明確實作的 xorshift32 與 Fisher–Yates 洗出完整 52 張牌，依七個牌列 1…7 張與 24 張牌庫建立候選。種子 93108 時取得第 50 個合格結果。

搜尋器將「翻一張、無限回收」的牌庫候選抽象成可巡迴取得的餘牌集合，以深度優先搜尋尋找合法解答；再把抽象步驟展開為逐張翻牌與實際回收。只有完整抵達四組 A…K 且至少有八次牌列間移牌的結果會保留。正式資料以每候選 12,000 節點為搜尋上限；搜尋逾時或未完成的候選一律丟棄，不標記為無解，也不標記為有解。

所有保留牌局都是不同的 **牌列點數配置**：即使完全忽略花色和牌庫順序，50 個牌列配置仍然各不相同。因此不是用花色重命名、牌庫排列或左右挪動同一牌桌湊數（起手各列張數唯一，按張數正規化後仍為 50 組）。這不代表某種隨機牌局勝率或難度評級；它是明確篩選的可解牌局合集。

每局內附完整 `witness`。`verify.cjs` 一方面呼叫 UI 使用的 `engine.js`，一方面用 **獨立實作** 的規則驗證器逐步檢查移牌、覆牌翻開、翻牌與回收，對照雙方完整狀態。它檢查初始結構、每一步 52 張唯一牌不變量、可移牌組、完成區進度、最後全數完成、50 組的獨特性。沒有把搜尋器的「找到」標記當作驗證結果。

已驗證摘要：

- 50 / 50 完整通過，50 個不同的初始牌列點數配置
- 共 11,215 個實際動作；每局完整解答 170–275 步（含翻牌與回收）
- 每局至少 13 次牌列間移牌；總計 399 次多張連續牌組移動
- 全部 1,050 張初始覆牌都在合法操作後翻開
- 6,708 次翻牌，406 次原順序回收

這些是附帶證明路線的統計，不表示最短解，也不表示玩家必須走同一路線。

## 可重現的驗證

從 `arcade/` 目錄執行（僅需 Node.js；不需安裝套件）：

```sh
node games/klondike/verify.cjs
node games/klondike/test.cjs
node --check games/klondike/engine.js
node --check games/klondike/ui.js
```

重新生成完全相同的資料：

```sh
node games/klondike/generate.cjs 50 12000
node games/klondike/verify.cjs --write-report
```

`verify.cjs` 是獨立的逐步審核；`test.cjs` 額外在所有 50 局的多個中間節點，比較各種合法／不合法動作的兩套規則結果，檢查完成區退牌、K 填空位、連續牌組、不可移動覆牌、不可錯花色入完成區、牌庫空時不能翻牌、有牌庫時不能回收、不改動舊狀態、惡意存檔狀態拒絕，以及 50 局完整歷史重播後逐步悔棋回起點。

## UI 與存檔

- 點牌選取，再點牌列／完成區移動；雙擊頂牌可送完成區。選取只更新樣式，不替換按鈕，以保留雙擊事件
- D 翻牌、U 悔棋、H 提示、Esc 取消；所有卡片和主要按鈕都能用 Tab／Enter 操作
- 無限次悔棋；每個狀態快照皆由合法動作產生
- 50 局編號選擇、下一局、重玩、時間、步數、進度與勝利畫面
- 提示只使用與當前牌面 **完全相同** 的證明節點；偏離時先詢問是否悔棋回最近證明節點，不把其他局面的步驟冒充提示
- 「示範解答」必先確認；若需回退玩家步驟會明說。可中途暫停、接手或悔棋。單純「查看解答」不改動進度
- 本機儲存合法動作歷史而不相信任意牌面；重載時從標準發牌重新重播並逐步驗證。儲存不可用仍可遊玩
- 桌面採單視窗牌桌＋操作側栏；窄螢幕維持讀得清楚的卡片，以牌桌區域左右滑動，操作列留在畫面內

QA 入口 `games/klondike.html`；唯讀 `window.KlondikeUI.snapshot()` 回報牌局、牌面、步數、計時、是否用協助、目前證明節點與示範狀態。沒有隱藏勝利捷徑。`window.KlondikeDeals.deals.length` 和 `KlondikeUI.proofCount` 均為 50。

人工 QA：翻牌／回收；點來源再點合法與不合法目的地；雙擊可入完成區的頂牌；多張牌組移動；悔棋至起點；重新整理恢復進度；選局／重玩取消與確認；偏離解答後的提示確認；查看解答不改牌面；示範暫停／恢復、完整勝利；桌面與窄螢幕。瀏覽器畫面與實際線上部署由整合流程驗證；此目錄的 Node 檢查不冒充視覺 QA。
