# 不等式數獨 / Futoshiki

A self-contained Traditional Chinese browser game. No CDN, network requests or backend. Open `../futoshiki.html`; return link is `../index.html`.

## Rules and source

An N × N Latin grid uses digits 1 through N exactly once in every row and column. Adjacent inequalities must hold. There is **no subgrid constraint**. Rule verification source: https://www.futoshiki.com/how-to-solve (checked 2026-10-02).

## Levels and progression

50 fixed unique-solution puzzles: ten each in five tiers. Sizes 4, 5, 6, 7 and 7. Later tiers reduce given digits. Every board is generated by randomized Latin-square backtracking, followed by removal of givens and inequalities only when capped solution counting still returns exactly one. This is not a relabeled cyclic-square level pack.

The distinctness certificate canonicalizes the positions of given cells and inequality edges across all eight rotations/reflections, ignoring both digit names and inequality directions. No two levels have the same canonical structure; this stronger comparison excludes rotational, mirror, and digit-renaming cosmetic copies.

## Regeneration and verification

From the repository root, using Python 3.10+ and Node 18+:

- `python arcade/games/futoshiki/generate.py` regenerates the fixed fixtures with seed 2026100207
- `node arcade/games/futoshiki/certify.cjs` independently counts up to two solutions and checks fixture solutions, geometry, duplicate structure and mutation rejection
- `node arcade/games/futoshiki/ui-test.cjs futoshiki` executes the shipped controller using DOM events on every level
- `python arcade/games/futoshiki/make_ui.py` regenerates both owned game shells, CSS and app files

The Python counter propagates bitset domains, hidden singles and inequalities. The independent JavaScript counter uses row/column assignment masks and cell-level backtracking. The runtime win engine checks rules on the submitted board and never compares it to the stored answer. `certification.json` records per-level count, independent search nodes, canonical SHA-256 fingerprints and fixture hash. `ui-certification.json` records controller coverage.

Additional regression command: `node arcade/games/futoshiki/engine-test.cjs`. This exercises deliberately nonunique fixtures, an alternative valid completion that differs from the stored answer, malformed input and contradiction-safe hints.

## Controls and behavior

Touch/click a cell and a digit. Keyboard: arrows navigate, 1–N fills, Delete/Backspace/0 clears, Z undoes, H gives a hint. The keypad hides out-of-range digits. Givens cannot be changed. Conflicting rows/columns/inequalities show red outlines.

Hints clear a wrong assignment before adding any correct value, so they never continue a mistaken branch. Undo retains hint-use history. Full-answer preview is read-only, preserves the user's board, marks assistance and never awards a win. Reset uses a confirmation dialog and keeps previous completion records. Finishing checks all rules; independent and assisted completions are distinguished.

LocalStorage key: `arcade.logic.futoshiki.v2`. Record lengths, integer ranges, givens, histories, level index and saved completion boards are validated before loading. Invalid JSON and blocked storage fall back safely; the rules dialog reports storage availability. No cross-device synchronization.

## QA scope

DOM integration covers 50 manual wins, 50 hint wins, 50 wrong-value recovery sequences, reset confirm/cancel, keyboard and focus, undo, answer preview, help, level boundaries, saved-state reload and malformed/blocked storage. Layout is designed for 1180 × 757 and narrow touch screens. Visual browser QA was not run in this assigned task because the supplied browser/local-preview route was unavailable; DOM tests are not a rendering claim.
